# Как задеплоить Flutter Web версию проекта на VPS (Docker)

Ниже описана инструкция для деплоя Flutter Web проекта на VPS через Gitlab Runner. 
Метод рассчитан на авторизацию по ssh ключам и отключенной парольной авторизации.

При этом подразумевается, что сама VM, на которой запускается CI собирает
сервисы в готовые docker образы и автоматически деплоит их на VPS.
(Либо вручную, либо посредством Docker Registry).

## Инструкция

1. Подключиться к linux vps серверу по ssh с sudo правами:
    - `ssh -i secret_key/path ADMIN_USERNAME@PROD_HOST`

2. Установить docker и docker-compose:
    - Он будет нужен для сборки итоговых образов
    - `sudo apt update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io`

3. (yandex docker registry) Создать сервисный аккаунт с правами:
    - `container-registry.images.scanner`
    - `container-registry.images.pusher`
    - `container-registry.images.puller`

4. (yandex docker registry) Создать новый "авторизованный" ключ на этом же аккаунте для доступа к docker registry: 
    - Алгоритм шифрования RSA_2048 или RSA_4096
    - Описание любое
    - Скачать файл с ключами (`authorized_keys.json`)

5. Добавить в GitLab CI secret variables содержимое `authorized_keys.json`:
    - `YC_AUTHORIZED_KEYS` - итоговая переменная с ключом

5. Создать связку ssh ключей для доступа к PROD VPS под пользователем ADMIN_USERNAME (если её ещё нет):
    - `ssh-keygen -t rsa -b 4096 -C "lms-prod-key"`

6. Добавить публичный ключ в .ssh/authorized_keys для пользователя ADMIN_USERNAME:
    - Так наша CI VM будет получать доступ к серверу по ssh для запуска деплоя.
    - `sudo mkdir -p /home/ADMIN_USERNAME/.ssh`
    - `sudo vim /home/ADMIN_USERNAME/.ssh/authorized_keys` и вставить публичный ssh ключ

5. Создать Secret Varialbes в GitLab CI:
    - SSH_PRIVATE_KEY - Приватная часть ключа, созданного ранее
    - PROD_USERNAME - Логин пользователя на prod VPS
    - PROD_HOST - Имя хоста на prod VPS (либо IP)

6. Теперь можно деплоить проект с CI VPS на PROD VPS:
    - ВАЖНО: докер нельзя запускать с sudo, только от текущего пользователя.
      Иначе сломается процесс авторизации.

    - Что будет происходить на CI VPS:
    - `docker build -t frontend .`
    - `docker tag frontend cr.yandex/<идентификатор_реестра>/frontend`
    - `docker push cr.yandex/<идентификатор_реестра>/frontend`

    - Что будет происходить на PROD VPS:
    - `docker pull cr.yandex/<идентификатор_реестра>/frontend`
    - `docker compose up -d`
